# 0.5.1 启动策略

默认只等待自检，不再设置固定的 15 秒延迟。Lilu 初始化时检查启动参数 `-e5pmwait15`，存在该参数则选择 15 秒预热，否则为 0 秒。

| 选择 | 允许接管的条件 |
|---|---|
| 无 `-e5pmwait15` | 20 个逻辑 CPU 各取得连续 8 个有效样本，且模式、内核、CPU 和 XCPM 健康条件通过 |
| 有 `-e5pmwait15` | 上述条件通过，并且从驱动服务启动／本次唤醒起已过去至少 15 秒 |

固定延迟和采样资格是独立条件：flag 只能增加等待，不能跳过采样，也不能把观察版变成控制版。默认控制 mode 仍为 2；`e5pm=1` 仍可选择观察，`e5pm=0` / `-e5pmoff` 仍禁用。新鲜度检查、功耗／热状态门控、原生 writer、请求读回和故障回退均保留。

要恢复旧版的额外预热，在 OpenCore 的 `NVRAM -> Add -> 7C436110-AB2A-4BBB-A880-FE41995C9F82 -> boot-args` 中追加空格和 `-e5pmwait15`，保留已有参数。参数需进入实际启动的 boot-args 后才会生效；实际选择以 IORegistry 的 `WarmupMinimumSeconds` 为准。修改参数或 EFI 中的 Kext 均需要重启；不支持热卸载。

IORegistry 诊断：

- `WarmupMinimumSeconds`：当前额外等待为 0 或 15 秒。
- `WarmupStartNs`：本次启动／唤醒周期的计时起点。
- `ControlFirstReadyNs`：首次通过所有控制门控的 uptime；0 表示尚未通过。它与 `WarmupStartNs` 的差值是首次可接管前的耗时，不等于首次实际频率覆盖时间。
- `SelfTestReadyMask` / `SelfTestRequiredMask`：仍需全部 20 个逻辑 CPU 通过，即 `0xFFFFF`。

测试覆盖默认模式在采样收齐后可早于 15 秒放行、flag 模式在 15 秒边界之前仍拒绝、两种模式均拒绝缺核／多核掩码、无起点和时钟倒退。原有无效或间隔过长样本、过期决策、热状态和故障等回归仍通过。观察版的控制路径继续编译禁用。

该版本只改变接管门控时机并增加诊断时间戳，没有改变私有函数指纹、挂钩范围或选频算法。原有 0.4.0、0.5.0 分发二进制保留原样。

## 默认启动与调频短测（2026-11-07）

目标为 macOS 15.8.2 / `24H232`，加载的 0.5.1 控制版 UUID 为 `58F49C23-613E-308C-9A95-A54DFBBE260E`，二进制摘要与分发 manifest 一致。实际 boot-args 未包含 `-e5pmwait15`，`WarmupMinimumSeconds = 0`。读取启动记录时已经进入 `controlling`，未手动切换模式或重新加载驱动；全核资格掩码为 `0xFFFFF`，并且已有实际覆盖及成功读回。

| 事件 | 本次时间 |
|---|---|
| 驱动服务启动 | 内核 uptime 0.939488991 秒 |
| 首次通过全部控制门控 | 内核 uptime 12.705285816 秒 |
| 服务启动至首次允许接管 | 11.765796825 秒 |
| 固定额外等待 | 0 秒 |

时间来自 `WarmupStartNs = 939488991` 和 `ControlFirstReadyNs = 12705285816`。测试期间 `CounterEpoch = 1`，首次允许接管时间始终不变，属于本次启动而非唤醒后的新周期。这证明本次在服务启动满 15 秒之前已经允许控制；约 11.77 秒包含等待各核采样及其余健康条件通过，未来启动耗时会随这些条件变化。

这里记录的是首次具备接管资格的时刻；没有单独记录第一条实际硬件覆盖的时间戳，也没有测量从按电源键、BIOS、OpenCore 或登录桌面起算的耗时。

随后运行轻载 6 秒、20 worker 资格负载 10 秒、20 worker 满载 20 秒、恢复 10 秒、单 worker 10 秒、最终轻载 10 秒，共 62 个 IORegistry 快照。以 1 秒间隔同步采集了 40 个 powermetrics 样本。

| 检查 | 结果 |
|---|---|
| 新增有效样本 | 40,380，覆盖全部 20 个逻辑 CPU |
| 满载持续采样 | 满载首末快照间每个逻辑核新增 545–896 个样本 |
| 覆盖与读回 | 15,549 次控制写入全部读回成功；回退和故障为 0 |
| 满载实际频率估计 | 各逻辑核平均 3.177–3.184 GHz，整体约 3.180 GHz |
| powermetrics 核对 | 稳定满载窗口 11 个样本，各逻辑核平均约 3.174 GHz，压力为 `Nominal` |
| 恢复轻载 | 最低请求 12 倍频；本轮新鲜低负载有效频率样本最低 1.278 GHz |

驱动频率统计使用满载阶段最初两个快照之后、决策有效、`busy_q8 >= 230`、距发布时刻不超过 250 ms 的样本（并发读取允许最多 10 ms 负差）。powermetrics 使用完整落在同一稳定满载时段内的窗口，覆盖全部 20 个逻辑核。数值摘要见 [results JSON](startup-policy-results.json)。

本次默认无固定等待的启动路径、持续升频及负载结束后的降频短测通过；实际满载接近原厂全核约 3.2 GHz，未承诺恒定 3.200 GHz。可选 `-e5pmwait15` 路径只有主机回归及静态检查，尚未单独重启验证。睡眠唤醒、长期稳定性、空闲功耗及吞吐 A/B 均未在此轮测试中验证。
